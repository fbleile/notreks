# Experimental protocol

This document is the human-readable counterpart of `src/notreks/catalog.py`.
The catalog is executable; this document explains the intended design and the
artifacts that must be retained. A generated plan is the version submitted to
a cluster and is the final authority for one execution.

## Common run contract

Every run has one graph identity, one data identity, one knowledge identity,
and one method identity. Seeds are derived from those identities and are
written to `run.json`. The same graph and observations are therefore shared
by vanilla, NOTREKS, and ablation methods.

The stages are:

1. `definition`: write the complete run specification;
2. `data`: generate or validate the graph, observations, and scale factors;
3. `knowledge`: enumerate available no-trek pairs, select the requested set,
   and write the pair list plus its canonical hash;
4. `solve`: run exactly the registered method and save the adjacency matrix,
   diagnostics, configuration, and runtime;
5. `evaluation`: translate the output to the declared evaluation target;
6. `aggregate`: collect successful rows and write failed or incomplete runs
   to a separate issue table;
7. `figure` and statistical analysis: consume aggregate tables only.

Each stage writes `status.json`. Exceptions are written to `error.txt` in the
same stage directory. A result is never inferred from a missing file.

## Synthetic recovery arms

The three synthetic arms use the same graph cells, sample sizes, seeds,
knowledge fractions, and evaluation metrics:

| arm | data-generating process | supplied methods |
|---|---|---|
| `main` | linear Gaussian SEM | FLOP, DAGMA, ablations, and order baselines |
| `main-misspec-linear-nongaussian` | linear non-Gaussian SEM | same method policy |
| `main-misspec-nonlinear-gaussian` | nonlinear Gaussian SEM | same method policy |

The graph cells are ER and WS with densities 2, 4, and 8 for dimensions 20,
50, and 100, excluding the unavailable d=20, density-8 cell. Sample sizes
are 100, 500, and 2000, with 20 graph replicates. The standard knowledge
fractions are 0, .25, and 1; an intermediate fraction is represented by five
independent knowledge rounds. DAGMA is omitted from d=100 production cells
for the runtime budget documented in the generated manifest.

The primary metrics are CPDAG SHD and CPDAG Ancestor-AID. All method outputs,
including order-based outputs, are evaluated against the same ground-truth
target. The reported solver labels and attempt budgets come from the catalog;
the numerical score and continuation settings are recorded in each solve
artifact.

## Prior-structure chromatic arm

`prior-structure-chrom` fixes the graph family and density to ER4 and WS4,
uses n=500, and generates fixed-size prior sets by target chromatic number
K. The target values are K=2,...,20; infeasible target values are recorded as
failed knowledge-stage constructions rather than silently replaced by random
sets. Each graph/K condition requests 50 distinct pair sets, with one solver
run per set. The d=50 cells use DAGMA+NOTREKS and the d=100 cells use
FLOP+NOTREKS, with vanilla baselines in the corresponding dimension policy.
The analysis cutoff is applied after construction: only K values represented
for at least 90% of generated graphs are included in the primary trend
analysis. The cutoff does not rewrite the raw output.

The knowledge artifact records the available-pair count, selected-pair count,
target K, canonical pair-set hash, and all seeds. This makes duplicate prior
sets and infeasible targets checkable independently of solver output.

## PSTrek versus TCC

`pstrek-vs-tcc` uses small ER graphs at dimensions 8, 10, and 12 and densities
2 and 4. It compares vanilla DAGMA, profile-Gaussian DAGMA with PSTrek,
profile-Gaussian DAGMA with TCC, and the two order-based score baselines under
the same supplied pair sets. This is a method comparison, not a claim that
PSTrek and TCC are the same objective: the two constraint terms and their
diagnostics remain distinct.

## External observational benchmarks

The CausalMan small/medium and CausalAssembly arms are registered separately
because their data are supplied rather than generated by the synthetic SEM
module. A manifest must provide observations, truth adjacency, node names,
and the supplied `knowledge_pairs` artifact. Projection metadata is required
when latent-projection diagnostics are intended.
The data stage validates array shapes and preserves the manifest provenance.
Evaluation uses the declared projection target and does not relabel it as
CPDAG SHD or CPDAG Ancestor-AID. Missing external files fail explicitly with
a stage traceback. Prior pairs are never inferred from the truth adjacency.
The catalog therefore refuses to generate an empty external plan when these
manifests have not been supplied.

## Exact feasibility motivation

`exact-feasibility-pilot` is a bounded combinatorial study of the restricted
DAG space. It is not a solver benchmark and has no sample size, method, or
recovery metric. Its set enumeration and graph-property tables are retained
separately from recovery results.

## What is retained

For every run, retain the plan, provenance, run specification, shared graph,
observations, scale factors, knowledge JSON, pair-set hash, solver adjacency,
solver diagnostics, status files, and traceback on failure. For every analysis,
retain the exact input table, analysis script or command, output table, and
figure-generation command. Cluster command files are derived from plans and
must not become the scientific source of truth.

The graph-clustered chromatic trend analysis is available as
`notreks-trend`. It first creates one graph--K cell mean per graph and K, then
fits graph fixed effects with CR1 cluster-robust uncertainty and a Student-t
reference with `G-1` degrees of freedom. All confirmatory tests use two-sided
p-values. Paired method comparisons use the Wilcoxon signed-rank test on
graph-matched metric differences, with multiplicity correction applied after
the test family is specified. The CLI accepts repeated
`--comparison treatment:baseline` arguments and reports Holm-adjusted
two-sided p-values for that family.
